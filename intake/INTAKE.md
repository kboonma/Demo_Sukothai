# การส่งข้อมูลดัชนีภัยแล้งเข้าระบบ (โครงการ สวก.)

ระบบเฝ้าระวังภัยแล้งรายตำบล จ.สุโขทัย รับดัชนีที่คำนวณจากภายนอกได้ เมื่อส่งตามรูปแบบนี้ ระบบจะ:

1. จับคู่กับตำบลทั้ง 86 ตำบล และแปลงเป็นค่ามาตรฐาน (z, ติดลบ = แล้ง)
2. แสดงเป็นชั้นแผนที่บน dashboard พร้อมค่าในแผงรายละเอียดตำบล
3. ทดสอบย้อนหลังกับฤดูแล้งที่ ปภ. ประกาศภัย (2562/63) และพิมพ์ผลเทียบกับดัชนีเดิม

ค่าเริ่มต้นคือ **แสดงผลเท่านั้น** ดัชนีจะยังไม่เปลี่ยนระดับเตือน จนกว่าทีมจะดูผลทดสอบแล้วตั้ง `use_in` เป็น `agri` หรือ `water`

## สิ่งที่ต้องส่ง

หนึ่งดัชนี = หนึ่งโฟลเดอร์ ชื่อโฟลเดอร์ใช้อักษรอังกฤษตัวเล็ก ตัวเลข และ `_` เช่น `arda_di/`

```
arda_di/
  meta.json   คำอธิบายดัชนี (แก้จาก _template/meta.json)
  data.csv    ข้อมูล (หรือ data.xlsx)
```

## data.csv

หนึ่งแถว = หนึ่งตำบล หนึ่งเดือน ถ้าคำนวณรายสัปดาห์หรือราย 10 วัน ส่งมาได้เลย ระบบจะเฉลี่ยเป็นรายเดือนให้

| คอลัมน์ | จำเป็น | รูปแบบ | หมายเหตุ |
| --- | --- | --- | --- |
| `pcode` | อย่างใดอย่างหนึ่ง | `TH640101` หรือ `640101` | รหัสตำบลแบบ HDX/กรมการปกครอง แนะนำที่สุด |
| `tambon_code` | อย่างใดอย่างหนึ่ง | `640101` | |
| `tambon` + `amphoe` | อย่างใดอย่างหนึ่ง | `ธานี`, `เมืองสุโขทัย` | ใส่ "ต." หรือ "อ." ก็ได้ ระบบตัดให้ |
| `date` | อย่างใดอย่างหนึ่ง | `2019-12` หรือ `2019-12-15` | ปี พ.ศ. ก็ได้ เช่น `2562-12` |
| `year` + `month` | อย่างใดอย่างหนึ่ง | `2562`, `12` | |
| ค่าดัชนี | จำเป็น | ตัวเลข | ชื่อคอลัมน์ตั้งใน `value_column` ของ meta.json |

- บันทึกเป็น UTF-8 (Excel: Save As → CSV UTF-8)
- ค่าที่ไม่มีข้อมูลให้เว้นว่าง หรือใช้ค่าเดียวตลอดไฟล์ แล้วระบุใน `missing_value`
- **ช่วงเวลา:** ยิ่งยาวยิ่งดี อย่างน้อยต้องครอบคลุม 2561–ปัจจุบัน เพื่อทดสอบกับปีแล้ง 2562/63 ถ้าส่งค่าดิบ (`kind: raw`) ควรมีอย่างน้อย 15 ปี เพราะระบบต้องใช้ค่าในอดีตเพื่อคำนวณ "ค่าปกติ" ของแต่ละเดือน

## meta.json

| ช่อง | ค่า | ความหมาย |
| --- | --- | --- |
| `id` | `arda_di` | รหัสดัชนี ต้องไม่ซ้ำ |
| `name` | `ดัชนีภัยแล้ง สวก.` | ชื่อที่แสดงบน dashboard (สั้น ๆ) |
| `source`, `contact`, `method` | ข้อความ | แหล่งที่มา ผู้ติดต่อ และวิธีคำนวณโดยย่อ |
| `kind` | `zscore` | ค่าเป็นค่ามาตรฐานอยู่แล้ว (SPI, SPEI, SMI ฯลฯ) ระบบใช้ตามที่ส่งมา |
| | `raw` | ค่าดิบ (มม., %, คะแนน) ระบบแปลงเป็น z ด้วยอันดับเทียบเดือนเดียวกัน |
| | `percent_of_normal` | ร้อยละของค่าปกติ (100 = ปกติ) แปลงแบบเดียวกับ raw |
| | `class` | ระดับเป็นชั้น เช่น 0–3 ต้องใส่ `class_to_z` |
| `drier_is` | `lower` / `higher` | ค่าต่ำ = แล้ง (เช่น SPI) หรือค่าสูง = แล้ง (เช่น จำนวนวันฝนแล้ง) |
| `value_column` | `value` | ชื่อคอลัมน์ค่าดัชนีใน data.csv |
| `units` | `z`, `มม.`, `%` | หน่วยของค่าที่ส่ง |
| `missing_value` | `-9999` | ค่าที่หมายถึงไม่มีข้อมูล (ถ้ามี) |
| `class_to_z` | `{"0":0,"1":-1,"2":-1.5,"3":-2}` | เฉพาะ `kind: class` แปลงชั้นเป็น z (−1 = แล้งปานกลาง) |
| `use_in` | `display` | ทีมเป็นผู้เปลี่ยน: `agri` = นับเป็นสัญญาณฝนขาดใน CDI ขั้น Watch, `water` = นับเป็นสัญญาณขาดน้ำอีกหนึ่งตัว |

## ตรวจก่อนส่ง

ผู้คำนวณตรวจไฟล์ได้เองด้วยคำสั่งเดียว (ต้องมี Python, pandas, scipy):

```
python scripts/external_intake.py --check raw/external/arda_di
```

ผลที่ได้: จำนวนตำบลที่จับคู่ได้, ช่วงเวลา, แถวที่มีปัญหาพร้อมตัวอย่าง และสัดส่วนตำบลที่ ≤ −1 ในแต่ละฤดูแล้ง ถ้าดัชนีใช้ได้ ฤดูแล้ง 62/63 ควรสูงกว่าปีอื่นชัดเจน

## เมื่อได้รับข้อมูล (ทีมระบบ)

1. วางโฟลเดอร์ไว้ที่ `raw/external/<id>/` (โฟลเดอร์ `raw/` ไม่ขึ้น GitHub)
2. รัน `python scripts/compute_indices.py --raw raw/ --boundaries data/source/sukhothai_tambon_web.geojson --out data/`
3. ดู AUC และผลทดสอบย้อนหลังที่พิมพ์ออกมา (และใน `data/meta.json` → `external`)
4. ถ้าดัชนีดีกว่าหรือช่วยเสริมดัชนีเดิม ให้ประชุมตัดสินใจก่อนเปลี่ยน `use_in` แล้วรันใหม่

# ข้อมูลจากกรมชลประทาน: เขตชลประทานและอ่างเก็บน้ำ

## เขตชลประทาน → `raw/irrigation_tambon.csv`

ใช้ปรับระดับ "เตือนเกษตร": ตำบลที่พื้นที่เกษตร ≥ 50% อยู่ในเขตชลประทาน ต้องมีระดับแล้งเกษตรสูงขึ้นอีกหนึ่งขั้นจึงจะเตือน

| คอลัมน์ | ตัวอย่าง | หมายเหตุ |
| --- | --- | --- |
| `pcode` หรือ `tambon_code` | `TH640101` / `640101` | |
| `irr_share` หรือ `irr_pct` | `0.62` / `62` | สัดส่วนพื้นที่เกษตรในเขตชลประทาน |
| `source` | `RID irrigation area 2568` | แหล่งข้อมูล |

ถ้ากรมชลส่งมาเป็น shapefile ขอบเขตโครงการ ทีมระบบจะคำนวณสัดส่วนรายตำบลให้ ระหว่างรอใช้ค่าประมาณจาก notebook (เซลล์ "irrigation proxy") ได้

## อ่างเก็บน้ำ → `raw/reservoirs.csv`

แสดงเป็นจุดบนแผนที่ สีตามร้อยละน้ำในอ่าง (template: `intake/reservoirs_template.csv`)

| คอลัมน์ | ตัวอย่าง |
| --- | --- |
| `name` | อ่างเก็บน้ำห้วย... |
| `type` | ขนาดกลาง / ขนาดเล็ก |
| `tambon`, `amphoe` | |
| `lat`, `lon` | 17.1000, 99.7000 (WGS84) |
| `capacity_mcm` | ความจุ ล้าน ลบ.ม. |
| `storage_mcm` | ปริมาณน้ำปัจจุบัน ล้าน ลบ.ม. |
| `date` | วันที่ของข้อมูล `YYYY-MM-DD` |

แนะนำให้ส่งทุกสัปดาห์ในฤดูแล้ง (พ.ย.–เม.ย.)

**ดึงอัตโนมัติ:** อ่างขนาดกลาง 7 แห่งของสุโขทัยมีในระบบฐานข้อมูลน้ำในอ่างเก็บน้ำ กรมชลประทาน (app.rid.go.th/reservoir) ซึ่งเปิดสาธารณะ ไม่ต้องใช้รหัสผ่าน รันบนเครื่องที่ต่ออินเทอร์เน็ตได้

```
python3 scripts/fetch_rid_reservoirs.py            # ข้อมูลวันนี้ -> raw/reservoirs.csv
```

ไฟล์ที่ได้มีปริมาณน้ำวันเดียวกันของปีที่แล้ว (`storage_prev_mcm`) และน้ำใช้การได้ (`usable_mcm`) ด้วย แหล่งน้ำที่ไม่อยู่ในระบบนี้ (แก้มลิง อ่างขนาดเล็ก) เพิ่มแถวเองในไฟล์เดียวกันได้

# ข้อมูลจากหน่วยงานในจังหวัด → `raw/local/`

ทุกไฟล์ไม่บังคับ ระบบทำงานได้โดยไม่มี และแสดงสถานะ "มีแล้ว / ยังไม่มี" ในหัวข้อ "ตัวชี้วัดของระบบ" บน dashboard ตัวอย่างไฟล์อยู่ใน `intake/local/` ระบุตำบลด้วย `pcode` (เช่น `TH640101`) หรือ `tambon` + `amphoe` ก็ได้ บันทึกเป็น CSV UTF-8

## 1. ครัวเรือนที่ไม่มีประปา → `water_supply.csv` (กปภ. สาขาสุโขทัย / อปท. / สำนักงานท้องถิ่นจังหวัด)

| คอลัมน์ | ตัวอย่าง | หมายเหตุ |
| --- | --- | --- |
| `pcode` หรือ `tambon`+`amphoe` | `TH640101` | |
| `households` | `5200` | ครัวเรือนทั้งหมดในตำบล |
| `hh_no_tap` หรือ `tap_pct` | `310` / `94` | ครัวเรือนที่ไม่มีประปา (กปภ. หรือประปาหมู่บ้าน) หรือร้อยละที่มีประปา |
| `villages_no_tap` | `1` | หมู่บ้านที่ไม่มีระบบประปาเลย (ถ้ามี) |
| `source`, `date` | | |

ใช้: นับครัวเรือนที่อาจต้องส่งรถน้ำในตำบลระดับ "เตรียมแจกจ่ายน้ำ" และตำบลที่ไม่มีประปา ≥ 30% ของครัวเรือนนับว่าเปราะบางขึ้น 1 ขั้น

## 2. แผนส่งน้ำนาปรังฤดูแล้ง → `rid_allocation.csv` (โครงการชลประทานสุโขทัย)

| คอลัมน์ | ค่า | หมายเหตุ |
| --- | --- | --- |
| `pcode` หรือ `tambon`+`amphoe` | | ตำบลในเขตโครงการ |
| `napr_status` | `full` / `reduced` / `none` (หรือ `ปกติ` / `จำกัด` / `งด`) | แผนส่งน้ำเพื่อนาปรังฤดูแล้งนี้ |
| `project`, `plan_date`, `note` | | |

ใช้: ส่งปกติ = ลดระดับแล้งเกษตร 1 ขั้น · จำกัด = ไม่ลด · งดส่งน้ำ = เตือนเกษตรกรในเดือน พ.ย.–เม.ย. แม้ฝนยังไม่ขาด (เพื่อไม่ให้ลงทุนปลูกนาปรังโดยไม่มีน้ำ) · ถ้าไม่มีไฟล์นี้ ใช้สัดส่วนเขตชลประทานแทน

## 3. รายงานผลกระทบ → `impact_reports.csv` (อปท. / ที่ทำการปกครองอำเภอ / ปภ.จังหวัด / เกษตรจังหวัด)

| คอลัมน์ | ตัวอย่าง | หมายเหตุ |
| --- | --- | --- |
| `pcode` หรือ `tambon`+`amphoe` | | |
| `date` | `2026-11-15` | วันที่เกิดเหตุหรือวันที่รายงาน (พ.ศ. ก็ได้) |
| `type` | `water_request` / `water_truck` / `crop_damage` / `declared` | ขอน้ำ / เที่ยวรถน้ำ / พืชเสียหาย / ประกาศเขตภัย |
| `value`, `unit` | `12`, `เที่ยว` | |
| `source` | `อบต.บ้านตึก` | |

ใช้: วัดผลระบบ (เตือนล่วงหน้ากี่เดือน, ตำบลที่เกิดผลกระทบแล้วระบบเตือนทัน, ตำบลที่เตือนแล้วเกิดจริง) ร่วมกับประกาศเขตภัยของ ปภ. ปี 2562–63 ที่มีอยู่แล้ว ส่งทุกเดือนในฤดูแล้ง แม้เดือนที่ไม่มีเหตุ (แถวว่างก็มีประโยชน์ เพราะบอกว่าไม่เกิด)

## 4. แนวโน้มภูมิอากาศและปฏิทินเพาะปลูก → `outlook.json`

แก้ทุกเดือน (ตัวอย่างใน `intake/local/outlook.json`)

- `enso.nino34`, `enso.month`, `enso.source`: ค่า Niño 3.4 ล่าสุดจาก NOAA CPC ENSO Diagnostic Discussion (ออกต้นเดือน)
- `tmd.rain_category`: `below` / `near` / `above` จากการคาดหมายลักษณะอากาศราย 3 เดือนของกรมอุตุนิยมวิทยา (ภาคเหนือตอนล่าง) พร้อม `period`, `rain_pct_of_normal` (ถ้ามี), `source`
- `crop_calendar.naprang_plant_month`, `warn_by_month`: เดือนเริ่มปลูกนาปรังและเดือนที่ควรเตือนเกษตรกร (ค่าตั้งต้น ธ.ค. / พ.ย. ให้เกษตรจังหวัดยืนยัน)
